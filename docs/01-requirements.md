# UK Rental Map（英国租房地图）- 需求概述文档 v0.1

## 1. 产品愿景

### 1.1 使命宣言（Why）
让在英国的中国留学生不再为租房信息的碎片化、不透明和虚假中介所困扰，用一张地图就能直观、高效、真实地找到理想住所。

### 1.2 核心原则（How）
- 原则1：**地图即产品** —— 所有信息围绕地图展开，位置和价格一目了然，抛弃传统列表式检索
- 原则2：**真实优先** —— 以真实用户体验替代中介话术，UGC内容是核心竞争力
- 原则3：**主动触达** —— 用户不需要反复刷页面，有匹配房源时系统主动提醒

### 1.3 产品形态（What）
Web端租房信息聚合平台（移动端优先响应式），以交互地图为核心界面，聚合各大租房网站数据 + 用户自发布房源，支持发布需求和房源提醒，以及真实租房体验分享。

## 2. 目标用户

### 2.1 主要用户画像
- **角色**：在英国的中国留学生
- **年龄**：18-28岁
- **痛点**：
  - 在小红书上看租房信息，充斥中介广告，难辨真假
  - Rightmove等平台检索不直观，不能按学校/公寓名筛选
  - 短租/转租信息散落在微信群、小红书、各种群聊中，信息时效差
  - 无法获取真实住户体验，只能看中介精修照片和话术
- **现有解决方案**：小红书搜帖+Rightmove/Zoopla逐个查+微信群/朋友圈打听
- **使用场景**：开学前集中找房（8-9月高峰）、学期中临时转租、毕业找工作换城市

### 2.2 次要用户画像
- **角色**：在英国的华人房东/转租者
- **痛点**：房源发布渠道有限，只能发微信群/小红书，覆盖面窄
- **需求**：快速发布房源信息，精准触达目标租客

### 2.3 核心Job-to-be-Done
**主Job**：当我（中国留学生）即将去英国/在英国需要租房时，我想要在一个平台上直观地看到所有可用房源的位置和价格，以便快速找到性价比高且真实可靠的住所。

**相关Job 1**：当我想了解某个公寓/区域的真实居住体验时，我想要看到真实住户的评价，以便做出更有信心的决策。

**相关Job 2**：当我有短租/转租需求但找不到合适房源时，我想要发布需求并在有匹配房源出现时立即收到通知，以便不错过任何机会。

**相关Job 3**：当我有房子要出租/转租时，我想要在一个目标租客集中的平台上发布信息，以便快速找到靠谱的租客。

## 3. 价值主张

### 3.1 核心问题（Top 3）
1. **信息碎片化**：租房信息散落在Rightmove、Zoopla、小红书、微信群等多个渠道，留学生需要在多个平台来回切换
2. **检索不直观**：现有平台不支持按城市/学校/公寓名直接定位，地理位置感知差
3. **信息不真实**：中介泛滥、精修图片误导、缺乏真实用户反馈

### 3.2 独特价值主张
一张地图看清英国所有房源——位置、价格、真实体验，一目了然，告别中介话术和信息差。

### 3.3 竞争优势
- vs 小红书：专业化垂直平台，地图交互 > 刷帖模式，结构化数据 > 非结构化帖子
- vs Rightmove/Zoopla：中文界面、按城市/公寓名筛选、地图聚焦交互更直观、真实用户体验评价
- vs 微信群：信息持久化、可检索、不会被刷屏淹没

## 4. 解决方案概述

### 4.1 核心功能（Top 3 + 扩展）
1. **地图交互浏览**：以地图为核心界面，支持按城市/区域筛选后聚焦，缩放地图直观看房源位置和价格标注
2. **用户自主发布**：用户可在地图上发布短租/长租的出租信息
3. **需求匹配提醒**：用户可发布租房需求（区域、价格范围、短/长租），匹配房源出现时即时提醒
4. **真实体验评价**：用户可在地图上对住过的公寓/房源留下真实体验评价

### 4.2 产品边界
- **做**：
  - 地图交互展示房源（位置+价格+基本信息）
  - 城市/区域/公寓名筛选
  - 用户发布出租信息
  - 用户发布租房需求 + 匹配提醒
  - 真实体验评价（文字）
  - 纯中文界面
  - 移动端优先响应式

- **不做**：
  - 不做在线签约/支付
  - 不做中介入驻系统
  - 不做房源真实性人工审核（MVP阶段）
  - 不做即时通讯/聊天功能
  - 不做房价走势/数据分析
  - 不做英文版本（MVP阶段）

### 4.3 Appetite（投入预算）
- 时间预算：1-2周
- 人力预算：Claude全栈开发
- 复杂度级别：Small Batch
- **风险标注**：全部4个核心功能在1-2周内完成压力较大，需在需求澄清阶段精确划分P0/P1边界

## 9. Opportunity Solution Tree

- **期望成果**：月活用户数≥500，地图交互使用率≥70%
  - **机会1**：租房信息碎片化
    - 方案A：爬虫聚合主流平台房源到地图
    - 方案B：纯UGC模式用户自主发布
    - 方案C（选定）：爬虫+UGC结合
  - **机会2**：检索方式不直观
    - 方案A：传统列表+筛选器
    - 方案B（选定）：地图为核心界面，城市筛选聚焦
  - **机会3**：缺乏真实信息
    - 方案A：引入房源审核机制
    - 方案B（选定）：UGC真实体验评价
  - **机会4**：信息时效性差
    - 方案A：定时爬取更新
    - 方案B（选定）：需求匹配主动提醒
