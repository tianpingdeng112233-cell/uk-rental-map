## 一页摘要（Executive Summary）

**产品名称**：UK Rental Map（英国租房地图）
**负责人**：CEO

**问题**：在英国的~15万中国留学生在租房时面临信息碎片化（多平台切换）、语言障碍（主流平台全英文）、信息不真实（中介泛滥、无真实体验反馈）三重困境。

**目标**：
- G1：上线3个月月活用户≥500
- G2：UGC真实评价≥50条
- G3：用户发布房源≥30条

**方案**：以交互地图为核心的中文租房信息平台，聚合房源数据并支持用户自主发布，提供真实居住体验评价系统，让留学生一张地图看清英国所有房源。

### 1. PRFAQ

#### 虚拟新闻稿

*中文地图交互，真实体验评价，让在英中国留学生不再为租房焦虑*

UK Rental Map今天正式上线，这是首个专为在英中国留学生打造的中文租房地图平台。用户只需选择城市，地图自动聚焦，所有房源的位置和价格一目了然，支持按价格、房型、短/长租筛选，彻底告别在Rightmove和小红书之间来回切换的痛苦。

在英国租房一直是中国留学生最头疼的事情之一。主流平台全英文、检索不直观，小红书上充斥中介广告，微信群信息转瞬即逝。更关键的是，没有任何平台能告诉你"住在这里到底怎么样"。

UK Rental Map通过真实体验评价系统解决了这个问题。住过的人可以对交通、安全、性价比等维度打分并留下文字评价，帮助后来者做出有信心的决策。同时，用户可以直接在地图上发布自己的出租/转租信息，精准触达目标租客。

#### 外部FAQ
1. **Q: UK Rental Map是做什么的？**
   A: 一个中文的英国租房地图平台。在交互地图上浏览房源、看位置和价格、读真实评价、发布出租信息。

2. **Q: 和Rightmove/Zoopla有什么不同？**
   A: 三个核心区别：(1)中文界面 (2)可以按城市/公寓名直接筛选，地图交互更直观 (3)有真实住户体验评价，这是任何英文平台都没有的。

3. **Q: 多少钱？**
   A: 完全免费。浏览、发布、评价全部免费。

4. **Q: 房源数据从哪来？**
   A: 两个来源：编辑团队精选录入的主流平台房源 + 用户自主发布的出租/转租信息。

5. **Q: 我发布的信息会立即显示吗？**
   A: 为保证信息质量，发布的出租信息需经过审核后才会显示在地图上，通常在24小时内完成。

6. **Q: 支持哪些城市？**
   A: 目前支持8个留学生热门城市：伦敦、曼彻斯特、伯明翰、爱丁堡、利兹、格拉斯哥、布里斯托、谢菲尔德。

7. **Q: 我的个人信息安全吗？**
   A: 密码加密存储，全站HTTPS传输，符合GDPR基本要求。联系方式仅在你发布信息时展示。

#### 内部FAQ
1. **Q: 为什么现在做这个？**
   A: 2025年中国留学生申请英国大学创新高，市场在增长。且无任何竞品服务华人私人租赁市场。

2. **Q: 最大的风险是什么？**
   A: 冷启动——需要在上线前手动准备200个种子房源和10条种子评价。

3. **Q: 技术上最大的挑战？**
   A: 地图性能（大量标注点的渲染和聚合）和地理编码（地址转坐标）。

4. **Q: 商业模式？**
   A: MVP阶段免费，验证需求后考虑广告、增值服务等方向。

### 2. 产品愿景

#### 2.1 使命宣言（Why）
让在英中国留学生不再为租房信息的碎片化、不透明和语言障碍所困扰，用一张地图就能直观、高效、真实地找到理想住所。

#### 2.2 核心原则（How）
1. **地图即产品** —— 所有信息围绕地图展开，位置和价格一目了然
2. **真实优先** —— UGC真实体验替代中介话术
3. **主动触达** —— 未来用匹配提醒替代反复刷页面（V2）

#### 2.3 产品形态（What）
Web端响应式应用（移动端优先），纯中文界面，以交互地图为核心。

### 3. 目标与非目标

#### 3.1 Goals
| # | 目标 | 衡量指标 | 目标值 | 时间线 |
|---|------|---------|--------|--------|
| G1 | 成为留学生认知的找房工具 | 月活用户数 | ≥500 | 上线3个月 |

| G3 | 启动供给端自增长 | 用户发布房源数 | ≥30条 | 上线3个月 |

#### 3.2 Non-Goals（明确不做）
1. **不做爬虫自动聚合** —— GDPR法律风险，MVP用人工录入替代
2. **不做英文版本** —— 聚焦华人垂直市场
3. **不做在线签约/支付** —— 产品边界外
4. **不做即时通讯** —— 复杂度高且非核心价值
5. **不做需求匹配提醒** —— 延后到V2，初期用户少匹配无意义
6. **不做房价走势分析** —— 产品边界外
7. **不做移动端App** —— Web响应式即可

## 第二部分：详细需求

### 6. 用户旅程与场景

#### 场景1: 开学前找房（核心场景）
- **Persona**：李小雨
- **时间/地点**：8月，中国家中，手机
- **行为序列**：
  1. 打开UK Rental Map → 看到英国全景地图
  2. 选择"伦敦" → 地图平滑聚焦到伦敦
  3. 放大到UCL附近 → 看到周围房源标注和价格
  4. 设置筛选：£600-800/月，长租，单间
  5. 点击"£680/月"标注 → 弹出概要卡片
  6. 点进详情 → 看到3条真实评价，平均4.2星
  7. 评价说"交通方便但隔音差" → 记下备选
  8. 继续浏览对比其他房源
- **情绪**：焦虑 → 安心 → 有信心

#### 场景2: 紧急短租
- **Persona**：王大力
- **时间/地点**：工作日晚上，曼彻斯特，电脑
- **行为序列**：
  1. 选择"爱丁堡" → 筛选短租
  2. 发现只有2个短租房源 → 失望但记下
  3. 浏览完离开（V2可发布需求等提醒）

#### 场景3: 转租发布
- **Persona**：张姐
- **时间/地点**：周末，伦敦家中，手机
- **行为序列**：
  1. 注册登录 → 点击"发布出租"
  2. 在地图上标注位置/输入地址
  3. 填写信息：£750/月，短租3个月，1室
  4. 上传照片，写描述，提交
  5. 等待审核 → 审核通过 → 显示在地图上
  6. 有人通过留的联系方式联系她

#### 7.2 功能详细描述

##### F1: 地图展示房源

**期望成果**：用户打开网站即看到地图，无需学习成本即可开始浏览房源。

**Product Kata**：
- 当前状态：用户在Rightmove用邮编搜索，看到列表，不知道位置关系
- 目标状态：用户看到地图，一眼看到房源分布和价格
- 障碍：用户习惯了列表模式
- 行动：地图为默认首屏，标注清晰直观

**用户故事**：作为李小雨，我想要在地图上直观看到房源位置和价格标注，以便快速了解目标区域的租房情况。

**验收标准**：
- Given 用户打开网站 When 页面加载完成 Then 显示英国全景地图，可缩放拖动，首屏加载≤2秒
- Given 地图上有房源 When 用户缩放到合适级别 Then 每个房源显示价格标注（如"£680"）
- Given 房源密集区域 When 缩放级别较远 Then 标注聚合为cluster显示数量（如"23个房源"）
- Given 用户在手机上 When 页面加载 Then 地图占主体区域，支持触屏缩放/拖动

**边界条件**：
- 地图缩放范围：英国全境 ↔ 单条街道
- 标注聚合阈值：同一视区内>20个标注时开始聚合
- 无房源区域：正常显示地图，不显示标注
- 网络慢时：先加载地图底图，标注异步加载，显示loading

##### F2: 城市筛选聚焦

**期望成果**：用户选择城市后，地图自动飞到目标城市，减少手动操作。

**用户故事**：作为李小雨，我想要选择"伦敦"后地图自动聚焦到伦敦，以便快速看到该城市的房源。

**验收标准**：
- Given 筛选栏显示城市列表 When 用户选择"伦敦" Then 地图平滑动画飞到伦敦，缩放到合适级别
- Given 地图聚焦到某城市 When 聚焦完成 Then 只显示该城市范围内的房源
- Given 城市列表 When 用户查看 Then 至少包含：伦敦、曼彻斯特、伯明翰、爱丁堡、利兹、格拉斯哥、布里斯托、谢菲尔德
- Given 用户已选城市 When 用户点击"全部城市"或清除筛选 Then 地图回到英国全景

**边界条件**：
- 城市坐标和缩放级别预设（硬编码8个城市的中心坐标和zoom level）

##### F3: 高级筛选

**期望成果**：用户可以精确过滤到符合自己条件的房源。

**用户故事**：作为李小雨，我想要按价格、房型、短/长租筛选，以便只看到符合我条件的房源。

**验收标准**：
- Given 筛选器 When 用户设置价格范围（如£500-£800） Then 地图只显示该价格区间的房源
- Given 筛选器 When 用户选择"短租"或"长租" Then 只显示对应租期类型
- Given 筛选器 When 用户选择房型（Studio/1室/2室/3室+） Then 只显示对应房型
- Given 多个筛选条件 When 条件变更 Then 地图标注实时更新，响应≤500ms
- Given 筛选结果为空 When 无匹配房源 Then 显示"暂无匹配房源，试试调整筛选条件"

**边界条件**：
- 价格范围：£0 - £5000/月，步长£50
- 房型选项：Studio、1室、2室、3室、4室+
- 租期选项：短租（≤6个月）、长租（>6个月）、全部
- 筛选条件组合上限：所有条件可任意叠加

##### F4: 房源详情页

**期望成果**：用户获取足够信息来判断是否值得联系。

**用户故事**：作为李小雨，我想要点击标注查看完整房源信息，以便决定是否联系。

**验收标准**：
- Given 用户点击地图标注 When 标注被选中 Then 弹出信息卡片：价格、房型、短/长租、来源、概要
- Given 信息卡片 When 用户点击"查看详情" Then 进入详情页
- Given 详情页 When 房源来自编辑录入 Then 显示：来源平台名称、原始链接、价格、房型、地址、描述
- Given 详情页 When 房源来自用户发布 Then 显示：所有发布字段（价格、房型、入住日期、照片、小区名、设施标签、bills情况、联系方式、描述）
- Given 详情页 When 该位置有评价 Then 显示评价区域（平均分+评价列表）

**边界条件**：
- 照片展示：最多10张，支持左右滑动
- 联系方式：仅发布者填写的方式（微信号/手机号/邮箱）
- 原始链接：新窗口打开
- 无评价时：显示"暂无评价，成为第一个评价的人"

##### F5: 邮箱注册登录

**期望成果**：用户快速完成注册，浏览功能不强制登录。

**用户故事**：作为李小雨，我想要用邮箱注册登录，以便使用发布和评价功能。

**验收标准**：
- Given 未登录 When 浏览地图、筛选、查看详情 Then 正常使用，不强制登录
- Given 未登录 When 点击"发布"或"评价" Then 跳转登录页，登录后回到原操作
- Given 注册页面 When 用户填写邮箱+密码+昵称 Then 发送验证邮件
- Given 验证邮件 When 用户点击链接 Then 账号激活，自动登录
- Given 登录页面 When 输入正确的邮箱和密码 Then 登录成功

**边界条件**：
- 密码要求：至少8位，含字母和数字
- 昵称：2-20个字符
- 验证邮件有效期：24小时
- 登录态保持：7天

##### F6: 发布评价

**期望成果**：用户留下真实居住体验，为后来者提供参考。

**用户故事**：作为李小雨，我想要对住过的公寓打分和写评价，以便帮助其他留学生。

**验收标准**：
- Given 用户已登录 When 在地图上点击某位置的"留评价" Then 弹出评价表单
- Given 评价表单 When 用户对4个维度打1-5星（交通便利度、安全性、性价比、总体满意度）并写文字评价 Then 提交成功
- Given 地图上没有对应标注 When 用户想评价新位置 Then 可在地图上打点或搜索地址创建评价点
- Given 评价提交 When 提交成功 Then 评价立即显示（评价不需要审核）

**边界条件**：
- 评分：每个维度1-5星，必填
- 文字评价：10-500字，必填
- 每人对同一位置：只能评价一次，可编辑
- 评价不可删除（保证真实性），可联系管理员申请

##### F7: 查看评价

**验收标准**：
- Given 某位置有评价 When 查看详情 Then 显示各维度平均分（1位小数）和评价总数
- Given 评价列表 When 展示 Then 按时间倒序，显示：昵称、评分、文字、时间
- Given 无评价 When 查看详情 Then 显示"暂无评价，成为第一个评价的人"引导

##### F8: 发布出租信息

**期望成果**：房东/转租者快速发布信息，精准触达目标租客。

**用户故事**：作为张姐，我想要在地图上发布出租信息，以便找到靠谱的中国租客。

**验收标准**：
- Given 用户已登录 When 点击"发布出租" Then 显示发布表单
- Given 发布表单 When 用户定位位置 Then 支持两种方式：(1)地图打点 (2)输入地址搜索自动定位
- Given 表单必填字段 When 用户提交 Then 必须填写：位置、价格(£/月)、短/长租、房型、联系方式
- Given 表单可选字段 When 用户填写 Then 可填写：可入住日期、照片(≤10张)、小区名称、设施标签、bills包含情况、详细描述
- Given 提交成功 When 信息进入审核队列 Then 显示"已提交，等待审核（通常24小时内）"
- Given 审核通过 When CEO审核通过 Then 房源显示在地图上，通知发布者

**边界条件**：
- 价格范围：£1 - £9999/月
- 照片：单张≤5MB，支持JPG/PNG
- 设施标签预设：洗衣机、烘干机、洗碗机、花园、车位、独立卫浴、bills含、允许宠物
- 联系方式类型：微信号、手机号、邮箱（至少填一个）
- 每个用户最多同时发布5条出租信息

##### F9: 审核后台

**期望成果**：CEO能高效审核发布内容，保证平台质量。

**用户故事**：作为CEO，我想要在后台审核用户发布的出租信息，保证信息真实性。

**验收标准**：
- Given CEO登录后台 When 查看审核队列 Then 显示所有待审核信息，按提交时间排列
- Given 查看某条信息 When 点击"通过" Then 房源发布到地图上
- Given 查看某条信息 When 点击"拒绝"并填写原因 Then 通知发布者（邮件通知）
- Given 后台 When 查看统计 Then 显示：待审核数、今日通过数、总房源数、总用户数

**边界条件**：
- 后台入口：独立URL路径（/admin）
- 权限：仅CEO账号可访问
- 审核操作不可撤销（通过后如需下架，在房源管理中操作）

##### F10: 种子数据管理

**期望成果**：CEO能高效录入种子房源数据。

**验收标准**：
- Given CEO登录后台 When 点击"录入房源" Then 显示简化录入表单
- Given 录入表单 When 填写：来源平台、原始链接、价格、房型、短/长租、地址 Then 系统自动地理编码获取坐标
- Given 地理编码 When 地址解析成功 Then 在地图上预览标注位置
- Given 地理编码 When 地址解析失败 Then 允许手动在地图上打点

### 9. 数据需求

#### 9.1 数据模型（概念级）

**核心实体**：
- **User**：邮箱、密码(hash)、昵称、注册时间、角色(user/admin)
- **Listing**（房源）：位置(经纬度)、价格、房型、租期类型、来源(编辑/用户)、来源链接、描述、照片、设施标签、bills、联系方式、状态(待审核/已上线/已下架)、创建者、创建时间
- **Review**（评价）：位置(经纬度)、地址文本、交通评分、安全评分、性价比评分、总体评分、文字评价、创建者、创建时间
- **City**（城市配置）：城市名(中文)、中心坐标、默认缩放级别

**关系**：
- User 1:N Listing（一个用户可发布多个房源）
- User 1:N Review（一个用户可写多条评价，但同一位置只能一条）
- Listing N:1 City（房源属于某个城市）

#### 9.2 数据采集需求（埋点）

| 事件 | 触发时机 | 关键属性 | 用途 |
|------|---------|---------|------|
| page_view | 打开首页 | 来源渠道、设备类型 | 流量分析 |
| city_select | 选择城市 | 城市名 | 热门城市排行 |
| filter_apply | 应用筛选 | 筛选条件组合 | 了解用户偏好 |
| listing_click | 点击房源标注 | 房源ID、城市 | 热门房源 |
| detail_view | 查看详情页 | 房源ID、停留时长 | 内容质量 |
| review_submit | 提交评价 | 位置、各维度评分 | UGC增长 |
| listing_publish | 提交发布 | 城市、价格、房型 | 供给分析 |
| user_register | 注册完成 | 注册方式 | 转化漏斗 |

#### 9.3 数据隐私
- 用户密码bcrypt加密存储，不可逆
- 个人信息（邮箱、联系方式）仅用于平台功能，不对外共享
- 用户有权要求删除账号和所有关联数据
- 隐私政策页面必须在注册前展示

## 第三部分：度量与策略

### 10. 成功度量体系

#### 10.1 北极星指标
- **指标**：周活跃地图交互用户数（WAU-Map）
- **定义**：每周至少在地图上进行1次交互操作（缩放/拖动/点击标注/筛选）的独立用户数
- **目标值**：上线3个月达到300 WAU

#### 10.2 主要指标
| 指标 | 定义 | 目标值（3个月） | 数据来源 |
|------|------|----------------|---------|
| MAU | 月活跃用户 | ≥500 | 埋点 |
| UGC评价数 | 累计评价条数 | ≥50 | 数据库 |
| 用户发布房源数 | 累计用户发布的房源 | ≥30 | 数据库 |
| 注册转化率 | 访客→注册 | ≥10% | 埋点 |

#### 10.3 护栏指标
| 指标 | 定义 | 底线 |
|------|------|------|
| 首屏加载时间 | P95 | ≤3秒 |
| 发布审核时长 | 提交到审核完成 | ≤24小时 |
| 虚假信息率 | 被举报/下架的比例 | ≤5% |

#### 10.4 先导指标
| 指标 | 定义 | 信号含义 |
|------|------|---------|
| 首日地图交互率 | 新用户首日是否与地图交互 | >60%说明产品核心体验有效 |
| 评价转化率 | 查看评价的用户中写评价的比例 | >5%说明UGC机制可持续 |
| 详情页点击率 | 点击标注后查看详情的比例 | >40%说明信息卡片设计有效 |

### 11. 竞争分析摘要
- **Rightmove/Zoopla**：英文、无中文服务、幽灵房源多、不支持按城市名筛选
- **SpareRoom**：Freemium收费消息、诈骗多
- **uhomes**：只做学生公寓（PBSA），不覆盖私人租赁
- **小红书/微信群**：非结构化、中介泛滥、信息时效差
- **我们的空白市场**：中文 × 私人租赁 × 地图 × 真实评价

### 12. 商业模式
MVP阶段免费，核心成本极低（地图API免费额度+低成本托管）。V2潜在方向：房东付费置顶、增值服务、垂直广告。

### 13. 风险与缓解

#### 13.1 Pre-Mortem分析
假设上线6个月后MAU仅100（目标500），可能原因：

| 失败原因 | 概率 | 影响 | 预防措施 |
|---------|------|------|---------|
| 冷启动失败，上线时地图空荡 | 高 | 致命 | 上线前准备200个种子房源+10条种子评价 |
| 用户习惯微信群/小红书，不愿迁移 | 中 | 严重 | 地图体验必须远超替代品；在目标社群精准推广 |
| 地图加载慢，移动端体验差 | 中 | 严重 | 移动端优先开发；性能测试必须通过 |
| 无人发布评价，评价区空白 | 中 | 严重 | 种子评价+评价引导文案 |
| 错过8-9月找房高峰季 | 低 | 严重 | 尽快推进开发，目标6月底前上线 |
| 爬取数据法律纠纷 | 低 | 致命 | MVP不做爬虫，人工录入 |

#### 13.2 关键假设验证状态
| 假设 | 状态 | 证据 |
|------|------|------|
| 留学生面临租房信息碎片化 | ✅ 已验证 | 竞品分析+CEO亲身经历 |
| 无竞品服务华人私人租赁 | ✅ 已验证 | 竞品全覆盖分析 |
| 地图交互优于列表 | ⚠️ 部分验证 | Rightmove/Zoopla都有地图功能，说明有需求 |
| 用户愿意写评价 | ❓ 待验证 | MVP上线后验证 |
| 社群推广可获取用户 | ❓ 待验证 | MVP上线后验证 |

#### 13.3 依赖项
| 依赖 | 类型 | 风险等级 | 替代方案 |
|------|------|---------|---------|
| 地图API（Mapbox/Google Maps） | 技术 | 低 | 多个供应商可选 |
| 地理编码服务 | 技术 | 低 | Mapbox/Google/Nominatim |
| 邮件发送服务 | 技术 | 低 | Resend/SendGrid/Mailgun |
