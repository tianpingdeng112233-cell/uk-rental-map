# UK Rental Map - 需求分析与用户研究报告 v1.0

## 1. 研究概述

### 1.1 研究目标
验证以下核心假设：
1. 在英中国留学生（~15万人）在租房过程中确实面临严重的信息碎片化和语言障碍问题
2. 地图交互方式相比列表方式能显著提升找房体验
3. 现有竞品未能有效服务华人留学生的私人租赁市场需求
4. UGC真实体验评价能构成差异化竞争力

### 1.2 研究方法
- 竞品分析：对4个直接竞品 + 3个间接竞品进行功能对比和启发式评估
- 五力模型：分析行业竞争格局
- 用户心智模型：基于CEO亲身经验和Persona构建
- 体验地图：绘制完整租房旅程
- 商业模式画布：深化商业可行性分析

### 1.3 研究范围和局限
- 竞品分析基于公开信息和用户评价数据
- 用户研究基于CEO的亲身经验和Persona推演，未做大规模定量验证
- 市场数据基于公开统计，具体细分市场规模为估算

### 2.4 破坏性创新机会

**新市场破坏**：
- 现有平台完全忽视了~15万中国留学生的语言需求
- 这些用户被迫使用英文平台或非结构化的中文社交媒体
- 我们的机会：用中文+地图+UGC切入这个被忽视的细分市场

**低端破坏**：
- uhomes仅覆盖学生公寓（PBSA），不覆盖私人租赁市场
- 私人租赁市场价格通常比学生公寓低20-40%，是留学生的真实需求
- 我们的机会：用更轻量的方式覆盖私人租赁市场

### 2.5 差异化定位策略

**核心差异化三角**：
1. **中文界面** × **私人租赁** = 唯一服务华人留学生私人租赁需求的平台
2. **地图核心交互** × **城市/公寓名筛选** = 最符合留学生心智模型的找房方式
3. **UGC真实体验** = 现有任何竞品都没有的功能

**我们不追求的维度**：
- 房源数量：不追求超越Rightmove（100万+房源），聚焦精选
- 全用户覆盖：只服务华人留学生
- 交易闭环：不做签约/支付

## 3. 五力分析

| 力量 | 强度(1-5) | 关键发现 | 策略建议 |
|------|----------|---------|---------|
| 现有竞争 | 2（低） | 无直接竞品服务华人留学生私人租赁市场 | 快速占领空白市场 |
| 新进入者 | 3（中） | 技术门槛不高，但需要社区冷启动 | 用UGC内容构建网络效应护城河 |
| 替代品 | 4（高） | 微信群/小红书虽然体验差但用户习惯根深蒂固 | 必须做到体验远超替代品才能迁移用户 |
| 买方议价 | 4（高） | 用户切换成本几乎为零，选择多 | 靠内容粘性（评价数据）留住用户 |
| 供方议价 | 3（中） | 依赖地图API（Mapbox/Google）和爬虫稳定性 | 选择有竞争的供应商，保留切换选项 |

**关键洞察**：最大威胁不是竞品，而是替代品（微信群/小红书）。用户已经有了"凑合能用"的方案，迁移需要足够强的动力。地图的直观体验 + 真实评价的独特价值是迁移动力的关键。

## 4. 用户心智模型

### 4.1 用户行为链（李小雨找房）

```
1. 产生需求 → "下学期要换房/新生要找房"
2. 信息收集 → 小红书搜"伦敦租房"，微信群里问
3. 初步筛选 → 看了20个帖子，真假难辨，信息格式不统一
4. 平台搜索 → 打开Rightmove，输入学校邮编（如果知道的话）
5. 英文障碍 → 遇到不认识的房产术语（leasehold, ground rent等）
6. 位置困惑 → 搜到的房子不知道离学校多远，不了解区域安全性
7. 逐个对比 → 开多个标签页，手动对比价格和位置
8. 求助社交 → 截图发到微信群问"有人住过这个小区吗？"
9. 做决策 → 信息不充分情况下勉强选择
10. 入住反馈 → 住进去后发现和预期不符，在小红书吐槽
```

### 4.2 心智模型缺口

| 用户行为 | 产品支持 | 缺口类型 | 优先级 |
|---------|---------|---------|--------|
| 想知道学校附近有什么房子 | ✅ 城市筛选+地图浏览 | 无缺口 | - |
| 想比较不同区域的价格 | ✅ 地图标注价格 | 无缺口 | - |
| 想了解区域安全性 | ✅ 用户评价(安全维度) | 无缺口 | - |
| 想看真实住户评价 | ✅ 体验评价系统 | 无缺口 | - |
| 想知道房子离地铁站多远 | ⚠️ 部分 (地图可视但无明确标注) | 次要 | 中 |
| 想一键对比多个房源 | ❌ MVP不做 | 关键 | V2 |
| 想用中文看英文房产术语 | ❌ MVP不做术语翻译 | 次要 | V2 |
| 想知道朋友的推荐 | ❌ MVP无社交功能 | 次要 | V2 |
| 找到房后想在线签约 | ❌ 不做 | 产品边界外 | - |

**关键发现**：MVP功能集已覆盖用户行为链中最痛的5个环节（信息碎片化、位置困惑、英文障碍、求助社交、入住反馈），缺口主要在V2功能中。

## 6. 使用场景

### 场景1：开学前找房（高频核心场景）
- **时间/地点**：8月中旬，中国家中，晚上用手机
- **Persona**：李小雨
- **目标**：9月开学前找到伦敦的合租房
- **行为序列**：
  1. 打开UK Rental Map，选择"伦敦"
  2. 地图聚焦到伦敦，看到密密麻麻的房源标注
  3. 放大到学校(UCL)附近，看到周围的房源和价格
  4. 设置筛选：£600-800/月，长租，单间
  5. 看到几个标注，点击其中一个"£680/月"
  6. 弹出卡片：Kings Cross附近，1室，来自Zoopla
  7. 点进详情，看到有3条真实评价，平均4.2星
  8. 评价说"交通很方便，但隔音差"，记下了
  9. 继续浏览对比其他几个房源
- **情绪曲线**：焦虑 → 看到地图时安心 → 看到评价时有信心
- **隐含需求**：需要保存/收藏感兴趣的房源（V2功能）

### 场景2：紧急短租过渡（中频场景）
- **时间/地点**：工作日晚上，曼彻斯特，电脑
- **Persona**：王大力
- **目标**：下月去爱丁堡工作，找3个月短租
- **行为序列**：
  1. 打开网站，选择"爱丁堡"
  2. 筛选：短租，£500-700，任意房型
  3. 发现爱丁堡短租信息很少，只有2个
  4. 点击"发布需求"，设置：爱丁堡，£500-700，短租，单间
  5. 提交后系统提示"有匹配房源时邮件通知您"
  6. 3天后收到邮件："爱丁堡有新短租房源，£620/月"
  7. 点击链接查看详情，联系房东
- **情绪曲线**：着急 → 失望（房源少）→ 提交需求后稍安心 → 收到提醒时兴奋
- **隐含需求**：短租市场供给不足是冷启动的挑战

### 场景3：转租发布（低频但关键供给场景）
- **时间/地点**：周末下午，伦敦家中，手机
- **Persona**：张姐
- **目标**：回国3个月，转租自己的房间
- **行为序列**：
  1. 注册登录网站
  2. 点击"发布出租"
  3. 在地图上标注自己家的位置（或输入地址）
  4. 填写：£750/月，短租3个月，1室，可入住4月1日
  5. 上传3张房间照片，写描述"近地铁站，安静社区"
  6. 标注设施：洗衣机、厨房共享、bills包含
  7. 提交，等待审核
  8. 审核通过后收到通知
  9. 2天后有人通过留的微信联系她
- **情绪曲线**：期待 → 填写时稍嫌麻烦 → 发布成功后安心 → 有人联系时开心

## 8. 关键发现与建议

### 8.1 已验证的假设
1. ✅ **信息碎片化是真实痛点**：竞品分析确认4大平台均为英文、无中文服务、且用户投诉幽灵房源和诈骗
2. ✅ **~15万中国留学生是实在的市场**：2025年数据显示申请人数创新高，市场在回升
3. ✅ **无竞品服务华人私人租赁市场**：uhomes只做学生公寓，其他全英文
4. ✅ **地图交互是成熟技术**：Rightmove/Zoopla都有地图功能，技术可行

### 8.2 需要修正的假设
1. ⚠️ **"爬虫+UGC结合"需谨慎**：Rightmove/Zoopla有反爬机制和法律保护。建议MVP阶段以UGC为主，爬虫作为数据填充的辅助手段，且必须遵守robots.txt
2. ⚠️ **"立马提醒"需调整预期**：匹配提醒改为"30分钟内"而非"立即"，避免系统压力和邮件轰炸

### 8.3 新发现的机会
1. **冷启动策略**：可以先手动从Rightmove/Zoopla复制热门城市的房源数据（人工而非爬虫），快速填充初始内容
2. **差异化杀手锏**：没有任何竞品有"真实体验评价"功能，这是独一无二的
3. **季节性运营**：每年7-9月是找房高峰（开学季），集中在此期间做用户增长

### 8.4 风险警告
1. 🔴 **冷启动鸡蛋问题**：没有房源→没有用户→没有房源。需要在上线前准备初始数据
2. 🟡 **爬虫法律风险**：UK数据保护法和GDPR对数据爬取有严格规定，建议咨询法律意见
3. 🟡 **替代品粘性强**：微信群/小红书是留学生日常工具，迁移到新平台有惯性
4. 🟡 **UGC冷启动**：评价系统需要临界量才有价值，初期可能内容稀缺

### 8.5 对需求的修正建议
1. **数据源策略调整**：MVP阶段建议以"人工录入+UGC"为主，爬虫作为后续技术储备，降低法律风险
2. **冷启动数据准备**：上线前CEO手动录入每个热门城市至少20个真实房源作为种子数据
3. **新增需求建议**：考虑在V2加入"收藏房源"功能（体验地图中识别到的隐含需求）

## 9. 用户研究工具包

### 9.1 访谈提纲（供CEO在留学生群体中使用）

**开场（3分钟）**：
- 简单介绍，不透露产品方向
- "我在做一个关于留学生租房体验的小调查"

**背景（5分钟）**：
1. 你在英国哪个城市？读什么专业？
2. 你目前住的房子是怎么找到的？

**行为探索（10分钟）**：
3. 上次找房的完整过程是怎样的？从开始到签约花了多久？
4. 你用了哪些平台或渠道找房？
5. 在Rightmove/Zoopla上搜索时，你的第一步是什么？遇到什么困难？
6. 你有在小红书或微信群里找过房吗？体验如何？

**痛点挖掘（10分钟）**：
7. 找房过程中最痛苦/最浪费时间的环节是什么？
8. 你有被中介坑过或遇到虚假信息的经历吗？
9. 你入住后发现和预期不符的地方有哪些？
10. 如果有人问你这个公寓怎么样，你会怎么描述？

**概念验证（5分钟）**：
11. 如果有一个中文的网站，用地图展示英国的出租房源，你会用吗？
12. 如果能看到住过的人的真实评价和打分，对你找房有帮助吗？
13. 你愿意在这样的平台上留下自己的真实居住评价吗？

### 9.2 招募标准
- 在英国的中国留学生或近2年内有英国租房经历的华人
- 有过至少1次自主找房经历（非学校分配宿舍）
- 目标：访谈5-8人即可获得有效洞察

- 卡7-9月找房高峰季，6月底前上线效果最佳
