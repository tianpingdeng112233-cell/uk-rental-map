## 3. 详细问题清单

### 3.1 致命缺陷（P0）
无。

### 3.2 严重问题（P1）

**P1-01：PRD中"密码重置"流程缺失**
- **位置**：PRD F5（邮箱注册登录）
- **描述**：设计稿P04中有"Forgot Password?"链接，但PRD中未定义密码重置流程的验收标准和边界条件
- **影响**：开发时不知道密码重置邮件内容、链接有效期、重置规则
- **修改建议**：在PRD F5中补充密码重置用户故事和验收标准：
  - Given 用户点击"忘记密码" When 输入注册邮箱 Then 发送重置链接邮件
  - 重置链接有效期：1小时
  - 新密码规则同注册

**P1-02：设计稿品牌名与PRD不一致**
- **位置**：设计稿全局 vs PRD
- **描述**：Stitch生成的品牌名为"The Curated Navigator"，但PRD定义为"UK Rental Map"/"英国租房地图"。设计稿首页中文Logo写的是"英国租房地图"（正确），但登录页等处显示"The Curated Navigator"
- **影响**：品牌名不统一会导致用户困惑
- **修改建议**：统一为"UK Rental Map / 英国租房地图"。开发时以PRD定义的品牌名为准，替换设计稿中的"The Curated Navigator"

### 3.3 一般问题（P2）

**P2-01：设计稿首页缺少"留评价"入口**
- **位置**：设计稿01-首页.png 导航栏
- **描述**：PRD要求导航栏有"发布出租"和"留评价"两个按钮，设计稿导航栏只有"Publish"按钮，缺少"留评价"入口
- **修改建议**：开发时在导航栏补充"留评价"按钮

**P2-02：设计稿评价维度只有3个，PRD定义4个**
- **位置**：设计稿03-房源详情.png 评价区
- **描述**：设计稿评价区显示3个维度（Transport、Security、Value），但PRD定义4个维度（交通、安全、性价比、总体满意度）。缺少"总体满意度/Overall"
- **修改建议**：开发时按PRD的4维度实现，设计稿评价区改为2x2网格

**P2-03：设计稿后台缺少"评价管理"菜单的具体页面**
- **位置**：设计稿06-管理后台.png
- **描述**：后台左侧菜单有"Review Management"项，但未设计具体页面内容。虽然MVP阶段评价不需要审核，但管理员可能需要查看/删除不当评价
- **修改建议**：V1简化处理——评价管理页面展示所有评价列表，支持删除操作即可

**P2-04：PRD未定义房源过期/下架机制**
- **位置**：PRD F8（发布出租信息）
- **描述**：用户发布的出租信息没有自动过期机制。如果房子已出租但发布者忘记下架，会产生过期信息
- **修改建议**：添加规则——用户发布的房源默认90天后自动下架，下架前7天邮件提醒发布者续期

**P2-05：设计稿登录页有Google/Apple第三方登录，PRD只定义邮箱**
- **位置**：设计稿02-登录注册.png vs PRD F5
- **描述**：设计稿登录页底部有"Google"和"Apple"登录按钮，但PRD明确只做邮箱注册登录
- **修改建议**：开发时不实现第三方登录，按PRD的邮箱方案。设计稿中的Google/Apple按钮忽略

### 3.4 改进建议（P3）

**P3-01：建议增加房源详情页的分享功能**
- 用户可能想把房源链接分享给朋友/室友，建议在详情页添加"复制链接"按钮
- 设计稿中已有分享图标（心形+分享），可在开发时实现为复制链接

**P3-02：建议后台种子数据录入支持批量导入**
- 当前设计为逐条录入，200条种子数据逐条录入效率低
- 建议后续支持CSV批量导入

**P3-03：设计稿首页房源列表缺少"无结果"状态**
- 当筛选条件过于严格导致无匹配房源时，左侧列表应显示空状态引导

**P3-04：建议评价区增加"排序"功能**
- 当评价数量多时，支持按时间/评分排序

### 3.5 信息记录（P4）

**P4-01：设计稿使用了Google Maps实景地图**
- Stitch生成的首页使用了Google Maps。技术方案阶段需确认地图API选型（Google Maps vs Mapbox），考虑成本和中国用户访问速度

**P4-02：设计稿后台统计数字为示例数据**
- 后台Dashboard中的数字（1,284房源、8,921用户）是Stitch生成的示例数据，不代表实际预期。MVP实际数据会远小于此

## 5. 技术可行性评估结果

### 5.1 可行项
| 功能 | 技术方案方向 | 风险 |
|------|------------|------|
| 地图展示+标注+cluster | Mapbox GL JS / Google Maps API | 低 |
| 城市筛选聚焦 | 预设城市坐标+flyTo动画 | 低 |
| 筛选器 | 前端状态管理+API查询参数 | 低 |
| 邮箱注册登录 | JWT + bcrypt + 邮件验证 | 低 |
| 评价系统 | CRUD + 聚合查询（平均分） | 低 |
| 照片上传 | 云存储(S3/Cloudflare R2) + 前端压缩 | 低 |
| 审核后台 | 独立路由+管理员角色判断 | 低 |

### 5.2 风险项
| 功能 | 风险描述 | 缓解方案 |
|------|---------|---------|
| 地理编码（地址→坐标） | 英国地址格式复杂，免费API精度有限 | 使用Mapbox/Google Geocoding API，允许手动打点兜底 |
| 地图API成本 | Google Maps API超出免费额度后收费较高 | 优先选Mapbox（免费层50K请求/月），或Leaflet+OpenStreetMap（完全免费） |
| 邮件发送 | 验证邮件/提醒邮件需要可靠的邮件服务 | 使用Resend（免费100封/天）或SendGrid |

### 5.3 不可行项
无。所有MVP需求在技术上可行。
