# UK Rental Map - 需求澄清文档 v1.0

## 1. Persona档案

### Primary Persona: 李小雨
- **年龄/职业**：21岁，大二中国留学生，伦敦某大学商科
- **核心目标**：找到一个离学校近、性价比高的房子，避免被中介坑
- **使用场景**：
  - 暑假在国内，9月开学前急需找房（8月高峰期）
  - 手机上用碎片时间刷房源（通勤、课间）
  - 和室友一起合租，需要对比多个选择
- **痛点**：
  - 在小红书搜"伦敦租房"出来全是中介广告，分不清真假
  - Rightmove只能用邮编搜，不知道学校附近有什么公寓
  - 微信群里的转租信息一刷就过了，经常错过好房
  - 不知道某个公寓住起来到底怎么样，只能看中介精修照片
- **技术水平**：中等，熟练使用微信/小红书/淘宝，不排斥新应用
- **性格特征**：谨慎、怕踩坑、信任同龄人评价多于商家话术
- **代表性引用**："我就想看看学校附近到底有哪些房子，多少钱，住过的人觉得怎么样"

### Secondary Persona 1: 王大力
- **年龄/职业**：25岁，研究生毕业后工作签证，曼彻斯特
- **核心目标**：换工作要搬城市，找短期过渡房
- **使用场景**：
  - 突然接到offer需要2周内搬到新城市
  - 晚上下班后集中搜房
  - 需要短租1-3个月的过渡房
- **痛点**：
  - 短租信息在主流平台极少，大多是长租
  - 不了解新城市的区域安全性和交通便利度
  - 时间紧迫，无法逐个平台对比
- **技术水平**：较高，会用多个英文平台
- **代表性引用**："下个月就要去爱丁堡上班了，短租三个月的房太难找了"

### Secondary Persona 2: 张姐（房东/转租者）
- **年龄/职业**：28岁，在伦敦工作的华人，要回国3个月想转租
- **核心目标**：快速找到靠谱的中国租客接手自己的房间
- **使用场景**：
  - 回国前2-3周开始发布转租信息
  - 希望精准触达在英的中国人群体
- **痛点**：
  - 只能发微信群和小红书，覆盖面有限
  - 微信群信息很快被淹没
  - 无法展示房子的地理位置优势
- **代表性引用**："我的房间离地铁站走路5分钟，这个在帖子里说不直观，在地图上就一目了然"

### Anti-Persona: Mike（英国本地人）
- **描述**：30岁英国本地人，习惯用Rightmove/Zoopla，对中文界面无需求
- **为什么不为此人服务**：MVP纯中文界面，聚焦华人留学生垂直市场，不追求全用户覆盖

## 2. 用例文档

### 用例1: 地图浏览找房
- **主要参与者**：李小雨（租客）
- **前置条件**：无（无需登录即可浏览）
- **后置条件**：用户对目标区域的房源分布和价格有清晰认知
- **主成功场景**：
  1. 用户打开网站，看到英国全景地图
  2. 用户在筛选栏选择城市（如"伦敦"），地图自动聚焦到伦敦
  3. 地图上显示该城市的房源标注点（显示价格）
  4. 用户缩放/拖动地图浏览不同区域
  5. 用户点击某个房源标注点
  6. 弹出房源概要信息卡片（价格、房型、短/长租、来源）
  7. 用户点击详情进入房源详情页
- **扩展场景**：
  - 3a. 该城市暂无房源：显示"暂无房源，设置提醒当有新房源时通知您"
  - 5a. 用户想进一步筛选：使用筛选器（价格范围、房型、短/长租）过滤标注点
  - 7a. 房源来自爬虫：详情页显示来源网站名称和原始链接
  - 7b. 房源来自用户发布：详情页显示发布者信息和联系方式
- **触发频率**：高频，每次使用必经

### 用例2: 发布出租信息
- **主要参与者**：张姐（房东/转租者）
- **前置条件**：用户已登录
- **后置条件**：出租信息提交成功，进入审核队列
- **主成功场景**：
  1. 用户点击"发布出租"按钮
  2. 系统弹出发布表单
  3. 用户在地图上点击标注位置（或输入地址搜索定位）
  4. 用户填写信息：价格、短/长租、房型（几室）、可入住日期、照片上传、小区名称、设施标签、bills包含情况、联系方式、详细描述
  5. 用户预览信息
  6. 用户提交发布
  7. 系统提示"已提交，等待审核"
  8. CEO在后台审核通过后，房源显示在地图上
- **扩展场景**：
  - 3a. 用户不确定精确位置：输入公寓名称，系统自动匹配地理坐标
  - 6a. 必填字段未填：系统提示补全必填信息
  - 8a. 审核不通过：系统通知用户修改原因
- **触发频率**：中频，发布者行为

### 用例3: 发布租房需求并接收提醒
- **主要参与者**：王大力（租客）
- **前置条件**：用户已登录
- **后置条件**：需求已保存，匹配引擎开始监控
- **主成功场景**：
  1. 用户点击"发布需求"按钮
  2. 系统弹出需求表单
  3. 用户选择：目标城市、价格范围（最低-最高）、短/长租、房型
  4. 用户确认提交需求
  5. 系统保存需求并开始监控
  6. 当有新房源匹配需求时，系统发送邮件提醒
  7. 用户点击邮件链接直接查看匹配房源
- **扩展场景**：
  - 6a. 一次匹配多个房源：邮件中列出所有匹配结果
  - 6b. 连续匹配太多：邮件合并为每日摘要（防止轰炸）
  - 4a. 用户想修改已发布的需求：在"我的需求"页面编辑
- **触发频率**：低频发布，高频触发提醒

### 用例4: 留下真实体验评价
- **主要参与者**：李小雨（住过某房子的租客）
- **前置条件**：用户已登录
- **后置条件**：评价提交成功，展示在对应位置
- **主成功场景**：
  1. 用户在地图上找到自己住过的公寓/位置
  2. 用户点击"留下评价"
  3. 用户对4个维度打分（交通便利度、安全性、性价比、总体满意度），每项1-5星
  4. 用户撰写文字评价
  5. 用户提交评价
  6. 评价显示在该位置的评价列表中
- **扩展场景**：
  - 1a. 地图上没有对应位置标注：用户可以新建一个评价点（输入地址或地图打点）
  - 5a. 评价内容包含敏感词：系统提示修改
  - 6a. 其他用户查看评价：在房源详情页或地图标注点查看该位置的所有评价和平均分
- **触发频率**：低频，一次性行为

### 用例5: CEO后台审核
- **主要参与者**：CEO（管理员）
- **前置条件**：管理员已登录后台
- **后置条件**：待审核内容已处理
- **主成功场景**：
  1. CEO打开后台管理页面
  2. 查看待审核列表（出租信息）
  3. 点击某条信息查看详情
  4. 审核通过：信息发布到地图
  5. 或审核拒绝：填写拒绝原因，通知发布者
- **扩展场景**：
  - 2a. 无待审核内容：显示"暂无待审核信息"
- **触发频率**：取决于发布量，初期低频

## 3. 用户故事清单

### Epic 1: 地图浏览

#### Story 1.1 - 地图查看房源
- 作为**李小雨**，我想要在地图上直观看到房源位置和价格，以便快速了解目标区域的租房情况
- 验收标准：
  - Given 用户打开网站 When 页面加载完成 Then 显示英国全景地图，地图可缩放拖动
  - Given 地图上有房源数据 When 用户缩放到足够近 Then 每个房源显示价格标注
  - Given 用户在手机上访问 When 页面加载 Then 地图占据屏幕主体区域，交互流畅
- 优先级：Must

#### Story 1.2 - 城市筛选聚焦
- 作为**李小雨**，我想要选择一个城市后地图自动聚焦，以便快速定位到我关注的区域
- 验收标准：
  - Given 筛选栏有城市选项 When 用户选择"伦敦" Then 地图平滑动画聚焦到伦敦区域
  - Given 用户选择了城市 When 地图聚焦完成 Then 只显示该城市范围内的房源标注
  - Given 支持的热门城市列表 When 用户查看筛选选项 Then 至少包含伦敦、曼彻斯特、伯明翰、爱丁堡、利兹、格拉斯哥、布里斯托、谢菲尔德
- 优先级：Must

#### Story 1.3 - 高级筛选
- 作为**李小雨**，我想要按价格范围、房型、短/长租筛选房源，以便精确找到符合条件的房子
- 验收标准：
  - Given 筛选器展开 When 用户设置价格范围（如£500-£800） Then 地图只显示该价格区间的房源
  - Given 用户选择"短租" When 筛选生效 Then 只显示短租类型的房源
  - Given 用户选择"2室" When 筛选生效 Then 只显示2室房型的房源
  - Given 多个筛选条件叠加 When 条件变更 Then 实时更新地图标注
- 优先级：Must

#### Story 1.4 - 查看房源详情
- 作为**李小雨**，我想要点击地图上的标注查看房源完整信息，以便判断是否值得联系
- 验收标准：
  - Given 用户点击地图标注 When 标注被选中 Then 弹出信息卡片显示：价格、房型、短/长租、来源
  - Given 信息卡片显示中 When 用户点击"查看详情" Then 进入房源详情页
  - Given 房源来自爬虫 When 查看详情页 Then 显示来源网站名称和原始链接
  - Given 房源来自用户发布 When 查看详情页 Then 显示联系方式和照片
- 优先级：Must

### Epic 2: 用户发布

#### Story 2.1 - 发布出租信息
- 作为**张姐**，我想要在地图上发布我的出租信息，以便精准触达中国留学生租客
- 验收标准：
  - Given 用户已登录 When 点击"发布出租" Then 弹出发布表单
  - Given 发布表单 When 用户填写所有必填项（位置、价格、短/长租、房型、联系方式）并提交 Then 系统提示"已提交，等待审核"
  - Given 用户定位位置 When 用户在地图上点击或输入地址 Then 系统标注精确位置
  - Given 可选字段 When 用户上传照片/填写设施标签/bills信息 Then 信息保存完整
- 优先级：Must

#### Story 2.2 - 管理我的发布
- 作为**张姐**，我想要查看和管理我发布的出租信息，以便随时更新或下架
- 验收标准：
  - Given 用户已登录 When 进入"我的发布"页面 Then 显示所有已发布的信息及其状态（待审核/已上线/已下架）
  - Given 房源已上线 When 用户点击"下架" Then 房源从地图上移除
  - Given 房源待审核 When 用户想修改 Then 可以编辑后重新提交
- 优先级：Should

### Epic 3: 需求匹配提醒

#### Story 3.1 - 发布租房需求
- 作为**王大力**，我想要发布我的租房需求，以便系统帮我监控匹配房源
- 验收标准：
  - Given 用户已登录 When 点击"发布需求" Then 弹出需求表单
  - Given 需求表单 When 用户选择城市+价格范围+短/长租+房型并提交 Then 需求保存成功
  - Given 需求保存成功 When 提交完成 Then 系统提示"需求已保存，有匹配房源时将通过邮件通知您"
- 优先级：Must

#### Story 3.2 - 接收匹配提醒
- 作为**王大力**，我想要在有匹配房源出现时立即收到邮件通知，以便不错过好房
- 验收标准：
  - Given 用户有激活的租房需求 When 新房源匹配用户需求 Then 系统在30分钟内发送邮件通知
  - Given 匹配邮件 When 用户收到邮件 Then 邮件包含房源基本信息和直达链接
  - Given 一天内多次匹配 When 匹配次数>5 Then 合并为每日摘要邮件（防止轰炸）
- 优先级：Must

#### Story 3.3 - 管理我的需求
- 作为**王大力**，我想要管理我的租房需求，以便在找到房后关闭提醒
- 验收标准：
  - Given 用户已登录 When 进入"我的需求"页面 Then 显示所有需求及其状态
  - Given 需求活跃中 When 用户点击"关闭" Then 停止该需求的匹配和提醒
  - Given 需求已关闭 When 用户想重新开启 Then 可以激活该需求
- 优先级：Should

### Epic 4: 真实体验评价

#### Story 4.1 - 发布评价
- 作为**李小雨**，我想要对住过的公寓留下真实评价，以便帮助其他留学生做决策
- 验收标准：
  - Given 用户已登录 When 在地图上找到住过的位置点击"留评价" Then 弹出评价表单
  - Given 评价表单 When 用户对4个维度（交通、安全、性价比、整体）打1-5星并写文字评价 Then 提交成功
  - Given 地图上没有对应标注 When 用户想评价一个新位置 Then 可以在地图上打点或搜索地址新建评价点
- 优先级：Must

#### Story 4.2 - 查看评价
- 作为**李小雨**，我想要查看某个公寓的所有评价和平均分，以便了解真实居住体验
- 验收标准：
  - Given 某位置有评价 When 用户查看该位置详情 Then 显示各维度平均分和所有文字评价
  - Given 多条评价 When 查看评价列表 Then 按时间倒序排列，显示评价者昵称和评价时间
- 优先级：Must

### Epic 5: 用户系统

#### Story 5.1 - 邮箱注册登录
- 作为**李小雨**，我想要用邮箱注册登录，以便使用发布和评价功能
- 验收标准：
  - Given 未登录用户 When 点击"注册" Then 显示邮箱注册表单（邮箱+密码+昵称）
  - Given 注册表单 When 用户提交有效信息 Then 发送验证邮件，验证后账号激活
  - Given 已注册用户 When 输入邮箱和密码登录 Then 登录成功跳转首页
  - Given 浏览功能 When 用户未登录 Then 可以正常浏览地图和房源，但发布/评价需登录
- 优先级：Must

### Epic 6: 管理后台

#### Story 6.1 - 审核出租信息
- 作为**CEO**，我想要在后台审核用户发布的出租信息，以便保证平台内容质量
- 验收标准：
  - Given CEO登录后台 When 查看审核队列 Then 显示所有待审核的出租信息
  - Given 查看某条信息 When CEO点击"通过" Then 信息发布到地图上
  - Given 查看某条信息 When CEO点击"拒绝"并填写原因 Then 通知发布者修改
- 优先级：Must

## 4. 影响地图

### 业务目标：上线后3个月内月活用户达到500，UGC评价≥50条

| 参与者 | 期望行为改变 | 支持功能 |
|--------|------------|---------|
| 留学生租客 | 从多平台切换 → 来本站一站式找房 | 地图浏览、城市筛选、高级筛选 |
| 留学生租客 | 从被动刷信息 → 主动发布需求等提醒 | 需求发布、邮件提醒 |
| 留学生租客 | 从私下打听 → 在平台留下公开评价 | 真实体验评价 |
| 华人房东/转租者 | 从微信群发帖 → 来本站发布房源 | 发布出租信息 |

所有功能均可追溯到业务目标，无孤儿功能。

## 5. 事件流

### 核心流程1：租客找房
| 事件 | 命令 | 参与者 | 聚合 | 策略 |
|------|------|--------|------|------|
| 页面已加载 | 打开网站 | 租客 | 地图视图 | - |
| 城市已选择 | 选择城市 | 租客 | 筛选器 | 地图聚焦 |
| 筛选已应用 | 设置筛选条件 | 租客 | 筛选器 | 更新标注 |
| 房源已点击 | 点击标注 | 租客 | 房源 | 显示卡片 |
| 详情已查看 | 查看详情 | 租客 | 房源 | - |

### 核心流程2：发布出租信息
| 事件 | 命令 | 参与者 | 聚合 | 策略 |
|------|------|--------|------|------|
| 发布已发起 | 点击发布 | 房东 | 房源 | 检查登录 |
| 位置已标注 | 地图打点/地址搜索 | 房东 | 房源 | 地理编码 |
| 信息已填写 | 填写表单 | 房东 | 房源 | 字段校验 |
| 房源已提交 | 提交发布 | 房东 | 房源 | 进入审核队列 |
| 房源已审核 | 审核通过/拒绝 | CEO | 房源 | 通过→发布到地图；拒绝→通知修改 |

### 核心流程3：需求匹配提醒
| 事件 | 命令 | 参与者 | 聚合 | 策略 |
|------|------|--------|------|------|
| 需求已创建 | 发布需求 | 租客 | 需求 | 保存+启动监控 |
| 新房源已入库 | 爬虫/用户发布 | 系统/房东 | 房源 | 触发匹配引擎 |
| 匹配已命中 | 需求匹配 | 系统 | 匹配记录 | 发送邮件通知（30分钟内）|
| 邮件已发送 | 发送提醒 | 系统 | 通知 | 防轰炸：>5条/天合并为摘要 |

### 热点标注
- **热点1**：地图标注聚合 - 房源密集区域标注重叠，需要聚合策略（如cluster）
- **热点2**：爬虫数据去重 - 同一房源可能在Rightmove和Zoopla同时存在
- **热点3**：匹配引擎性能 - 新房源入库时需实时匹配所有活跃需求
