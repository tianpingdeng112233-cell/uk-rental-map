## 3. MoSCoW分级

### Must Have（必须有）
| 需求 | 理由 | 故事点 |
|------|------|--------|
| 地图展示房源 | 产品核心，没有它产品不存在 | 8 |
| 城市筛选聚焦 | 核心交互，没有它用户无法定位 | 3 |
| 高级筛选（价格/房型/租期） | 没有筛选的地图无法使用 | 5 |
| 房源详情页 | 点击标注必须能看到详情 | 5 |
| 种子数据录入工具 | 冷启动必须，空地图没有价值 | 3 |
| 邮箱注册登录 | 发布/评价功能的前置条件 | 5 |
| **合计** | | **29点（约55%）** |

### Should Have（应该有）
| 需求 | 理由 | 故事点 |
|------|------|--------|
| 真实体验评价（发布+查看） | 核心差异化功能，但没有它产品仍可用作找房工具 | 8 |
| 发布出租信息 | 供给端关键功能，但初期有种子数据兜底 | 8 |
| 发布审核后台 | 有发布就必须有审核 | 5 |
| **合计** | | **21点（约40%）** |

### Could Have（可以有）
| 需求 | 理由 | 故事点 |
|------|------|--------|
| 发布租房需求 | 锦上添花，初期用户少时匹配概率低 | 5 |
| 邮件匹配提醒 | 依赖需求发布功能，且技术复杂度较高 | 8 |
| 管理我的发布 | 初期发布量少，可后台直接管理 | 3 |
| 管理我的需求 | 同上 | 3 |
| **合计** | | **19点** |

### Won't Have（本次不做）
| 需求 | 理由 | 可能时机 |
|------|------|---------|
| 收藏房源 | 体验地图发现的隐含需求，V2做 | V2 |
| 多语言支持 | MVP纯中文，验证后考虑英文版 | V2+ |
| 在线签约/支付 | 产品边界外 | 不做 |
| 即时通讯 | 产品边界外 | 不做 |
| 房价走势分析 | 产品边界外 | V3+ |
| 爬虫自动聚合 | 法律风险，MVP用手动录入替代 | V2验证法律后 |

### MoSCoW检验
- ✅ Must Have（29点）占总量55%，未超过60%上限
- ✅ Must Have构成完整可用产品：用户可以在地图上浏览房源、筛选、查看详情
- ✅ Must + Should构成有竞争力的产品：加上评价系统和用户发布，差异化完整
- ✅ Won't Have中没有被错误排除的关键功能

## 4. Top 5聚焦清单

1. **地图交互浏览** - 产品的灵魂，用户打开网站的第一体验
2. **城市筛选 + 高级筛选** - 让地图可用的核心操作
3. **房源详情页** - 用户决策的信息载体
4. **真实体验评价** - 独一无二的差异化武器
5. **用户发布出租信息 + 审核** - 供给端的自增长引擎

### "避免做"清单（Top 5完成前不投入资源）
- 需求匹配提醒（邮件系统复杂，初期用户少无意义）
- 管理中心页面（初期直接在后台处理）
- 收藏功能
- 爬虫系统

## 6. 决策类型分类

### Type 1（不可逆决策）
| 决策 | 选项 | 最终决定 | 理由 |
|------|------|---------|------|
| 地图API选型 | Mapbox / Google Maps / Leaflet | 技术方案阶段决定 | 影响成本和性能 |
| 前端框架 | React / Vue / Next.js | 技术方案阶段决定 | 迁移成本高 |
| 数据库选型 | PostgreSQL / MongoDB | 技术方案阶段决定 | 地理数据需求影响选型 |
| 目标市场 | 华人留学生 | 已决定 | 差异化定位 |
| 产品语言 | 纯中文 | 已决定 | MVP聚焦 |

### Type 2（可逆决策）
| 决策 | 初始选择 | 调整机制 |
|------|---------|---------|
| 筛选维度和选项 | 城市/价格/房型/租期 | 上线后根据使用数据调整 |
| 评价维度 | 交通/安全/性价比/整体 | 上线后根据用户反馈调整 |
| 发布表单字段 | 详细版 | 可随时增减字段 |
| 邮件提醒频率 | 匹配后30分钟内 | 可调整 |
| UI布局和配色 | 设计阶段确定 | 随时可改 |
